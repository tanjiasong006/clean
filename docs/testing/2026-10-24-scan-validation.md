## 正确性覆盖

| 模块 | 已验证的行为 |
| --- | --- |
| 扫描与统计规则 | 嵌套目录聚合、空目录、大小排序；硬链接按路径分别计数，包括跨目录硬链接；目录数包含根目录 |
| 符号链接 | 不跟随普通、目录、悬空和循环链接；拒绝以链接为扫描根目录，包括带尾随分隔符或 `.` 的链接路径 |

| 打开目录后的变化 | 根目录或正在读取的目录路径被替换后，仍从原句柄读取元数据和内容，不转入同名新路径 |
| 失败与文件变化 | 根目录无效、目录读取失败、迭代器报错、文件在元数据读取前消失或增长；保留已有结果，不把失败目录当作空目录 |

## 合成性能基准

### 方法与复现

每轮生成十万条普通文件事件，按最多 1024 条事件更新：

1. 平铺目录：计入路径生成、目录聚合、大文件索引、目录排序索引更新及可见 ID 列表生成。
2. 深层聚合：父节点关系形成 96 层祖先链，仅测量事件生成与聚合，不创建真实的深层文件系统目录。

准备祖先节点与计时后的正确性断言不计入耗时。当前实现以独立程序优化编译，不启动 GUI：

```sh
perf_dir=$(mktemp -d)
rustc --edition=2024 -D warnings -O scripts/core_perf.rs -o "$perf_dir/core-perf"
"$perf_dir/core-perf"
```

## 真实文件系统压力测试

### 方法与复现

创建两万个临时稀疏文件，大小按文件编号对 8192 取余。执行真实后台扫描，通过容量为 8 的通道发送每批最多 128 条事件，接收端进行批量聚合并更新目录和大文件索引：

```sh
cargo test --locked large_directory_worker_pipeline -- --ignored --nocapture
```

测试校验扫描完整状态、文件数、总逻辑大小、各节点完整性、无扫描问题、目录排序与参考全量排序一致，以及大文件索引条目数。临时目录由测试自动清理。

### 本次结果

```text
20000 files, 157 bounded batches, scan + aggregation + indexes: 56.472334ms (354156 files/s)
test scanner::tests::large_directory_worker_pipeline ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 42 filtered out; finished in 2.71s
```

- 上述约 56.47 ms 仅包含后台扫描、事件传输、聚合和索引更新。
- 整个测试执行约 2.71 s，包含准备和清理临时文件；二者不可混为同一指标。
- 使用 Cargo 默认测试构建，不是应用的 release 构建；未启动 GUI，也没有 GUI 轮询间隔。
- 新建文件通常处于热缓存，文件很小或稀疏，不能据此推断冷盘、网络卷、大文件内容读取或用户主目录的吞吐。
- 扫描仅读取元数据，不读取文件内容；逻辑大小不等于物理分配或可释放空间。
