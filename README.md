# Clean

使用 Rust、GPUI 和 GPUI Kit 构建的磁盘空间分析工具。先支持 macOS，功能稳定后再适配 Windows。

当前已实现目录扫描与导航循环，并加入大文件分析和 macOS Finder 集成。架构和首版范围见 [AGENTS.md](AGENTS.md)。

## 当前功能

- 显式选择主目录、下载目录或其他目录，单个后台工作线程执行扫描。
- 增量显示已发现的文件路径数、目录数和已分配空间；扫描期间可以取消并保留已有结果。
- 按大小降序浏览目录和文件，显示已发现大小的占比；双击目录进入，通过面包屑或返回按钮导航。
- 每个目录保留选中条目和滚动位置，切换分析视图后恢复；支持复制完整路径、在 Finder 中定位选中项。
- 大文件视图汇总整个扫描范围内去重后的普通文件，按已分配空间降序显示，可选择全部文件、≥100 MiB、≥1 GiB 或 ≥10 GiB；支持跳转到所在目录并选中该文件。
- 单独显示所选卷的容量和当前用户可用空间；后台查询失败时明确提示，不影响目录扫描。
- 单独查看读取失败的路径与原因；未读完或含失败项的目录标记为不完整，不视为空目录。

偏好持久化、更多性能优化和 macOS 打包将在后续阶段加入。尚未实现删除或清理功能。

## 统计规则

只统计文件系统报告的**已分配空间**，不再汇总或展示文件逻辑长度。macOS 读取 `st_blocks × 512`，固定以 512 字节为单位换算，与 `statfs` 的文件系统块大小无关；以二进制单位显示（KiB、MiB、GiB）。普通文件和目录自身报告的分配量均计入，目录行还包含其子条目的贡献；因此目录自身有分配量时，子条目的占比之和可以小于 100%。符号链接和特殊文件不计入字节总数，不遍历符号链接。目录数量包含所选根目录。

硬链接在**每次扫描内按设备号与 inode 去重**，不是按路径或内容去重。同一文件的分配量归入本次扫描首次发现的路径及其祖先，其他路径保留在目录列表中，但标为“已去重”并显示计入的路径，不再增加目录或扫描总量。文件数仍为发现的普通文件路径数，另列去重路径数；大文件索引只收录首次发现的文件路径，包括分配量为零的稀疏文件。跨目录硬链接的归属取决于发现顺序，目录合计表示本次扫描分配到该目录的贡献，不是对该子目录单独执行扫描的结果；重新单独扫描该目录会重新去重并计量。去重表保留每个普通文件的身份与首个节点 ID，不复制路径，内存随唯一文件数增长，扫描线程结束后释放。

稀疏镜像只计入系统报告的已分配块，而不是其声明的数百 GiB 或 TiB 的逻辑长度。排查单个文件时，可使用 `stat -f 'allocated_blocks_512=%b hard_links=%l' /path/to/file` 对照 `du -k /path/to/file`；对于稀疏但尚未写入数据的文件，已分配空间可以为零，这不表示文件内容长度为零。

**已分配空间不等于独占占用或删除后可释放空间。** APFS 克隆、快照和共享数据不按 inode 去重，仍可能重复报告共享块；扫描也允许跨挂载点，不把总量限制在单个卷的容量以内。界面在总量超过所选卷容量时提示这些差异，不把总量截断，也不声称其与系统显示的磁盘已用总量一致。未纳入扫描范围的系统元数据等也不在扫描总量中。

读取失败或文件在读取元数据前消失，会保留其他结果并将扫描标记为不完整；根目录无法读取时显示失败。取消扫描也保留已发现的结果。扫描期间文件可能继续变化，大小取读取元数据时观察到的值，结果不是文件系统快照。已分配空间累加溢出时保留已发现条目，明确报告统计范围溢出，并将结果标记为不完整，不显示溢出目录的精确大小或占比。

macOS 扫描以打开的根目录句柄为锚点；子目录通过逐层 `openat` 且禁止跟随链接的方式打开，文件元数据使用相对目录句柄的 `fstatat` 读取。待扫描目录的设备号或 inode 变化时，记录问题并跳过替换内容。已打开的根目录或正在读取的目录被重命名后，仍读取原目录，不转入同名路径的新内容。因此结果中的路径是扫描时观察到的路径，之后可能不再有效。

目录列表的占比条以当前目录本次扫描计入的**已分配空间**为分母；大文件列表以整个扫描范围的已分配空间总量为分母。两者均不表示扫描进度。扫描总数不代表独占占用、磁盘容量或可释放空间。

卷容量与可用空间通过 macOS `statfs` 在开始扫描时单独查询（64 位块计数，按文件系统块大小换算），可用空间取当前用户可用块数。这不是可清理空间估算，也不计算 APFS 共享数据或可清除空间。Finder 定位不会解析符号链接，选中的是链接本身；目标消失或系统命令失败时显示错误。

## 开发环境

- macOS 15 或更高版本。
- Rust stable，包含 Cargo、rustfmt 和 Clippy；工具链要求见 `rust-toolchain.toml`。
- Xcode 或 Xcode Command Line Tools；使用 `xcode-select -p` 检查开发工具路径。

GPUI Kit 使用统一依赖入口，包含匹配的 GPUI、组件和默认图标资源。参考[官方安装说明](https://gpui-kit.com/docs/installation/)及[入门文档](https://gpui-kit.com/docs/getting-started/)。

## 运行与检查

仓库已包含 `Cargo.lock`，使用锁定的依赖运行和检查：

```sh
cargo run --locked
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --locked
```

首次构建会下载并编译 GPUI 依赖，耗时较长。扫描器的临时目录测试覆盖目录聚合、排序、符号链接、硬链接、取消、读取失败、扫描期间文件变化和后台批量更新。权限失败通过文件系统边界注入，以便测试在不同权限的环境中均可重复执行。额外覆盖目录及祖先目录被替换为符号链接、目录身份变化、打开目录后的路径替换、开始前/迭代期间取消、接收端断开、通道背压、160 层目录、稀疏大文件与特殊名称。批量聚合以逐事件参考算法校验不同批次边界，并测试统计溢出。额外测试覆盖大文件筛选边界、增量索引、视图切换与目录导航状态、卷容量换算，以及 Finder 命令的字面路径参数（不启动 Finder）。

## 项目结构

```text
src/main.rs       应用入口和窗口初始化
src/ui/           GPUI Kit 界面
src/scanner/      后台遍历、批量事件和取消
src/analysis/     大小排序、大文件增量索引和格式化
src/platform/     平台目录入口、macOS 卷查询和 Finder 集成
src/models/       扫描状态、条目和目录聚合
```

扫描和分析模块不依赖 GPUI。

- 单个后台扫描线程，容量为 8 的通道，每批最多 128 条事件。每批预分配缓冲区，通道满时施加背压，不无限缓存扫描事件。
- 扫描只持有根目录和常数数量的临时目录句柄，不为每个待扫描目录或每层祖先保留句柄；遍历不使用递归调用栈。
- 聚合按批次从子节点向父节点合并，每个受影响的祖先在一批中只更新一次。
- 当前目录与大文件使用有序索引；只更新新增条目及大小改变的目录，避免对全部结果反复排序。索引通过 `Arc` 共享不可变路径，不复制路径内容。
- 界面每约 16ms 消费更新，每轮最多 32 批，在批次之间检查约 4ms 的处理时间预算；可见 ID 列表最多每 100ms 重建一次，结束时立即刷新。时间预算不包括操作系统阻塞，也不是整帧耗时的硬上限。
- 结果列表仍为虚拟化渲染。扫描结果和索引目前保存在内存中，内存随发现的条目数增长，尚未做磁盘索引。

## 核心性能验证

历史实测环境、测试结果、基准数据和验证限制见 [2026-10-24 扫描验证记录](docs/testing/2026-10-24-scan-validation.md)。该记录保留了切换前的逻辑大小口径，不代表当前已分配空间口径的测试结果。

合成基准直接编译扫描结果聚合与分析模块，不启动 GUI，也不需要重新编译 GPUI：

```sh
perf_dir=$(mktemp -d)
rustc --edition=2024 -O scripts/core_perf.rs -o "$perf_dir/core-perf"
"$perf_dir/core-perf"
```

基准每次处理十万条目，分别测量平铺目录的聚合与索引更新，以及 96 层祖先的批量聚合。会校验条目数、总大小和排序，不设易受机器负载影响的时间阈值。这是内存合成基准，**不是磁盘扫描吞吐或 GUI 帧率**。

真实文件系统的手动压力测试会创建并自动清理两万个临时稀疏文件，验证后台扫描、有界通道、批量聚合和两个排序索引：

```sh
cargo test --locked large_directory_worker_pipeline -- --ignored --nocapture
```

测试输出不包含准备/清理文件的时间，也不包含 GUI 的轮询间隔；新建文件通常处于热缓存，不能直接外推到冷盘、网络卷或用户主目录。

## 版本管理

主分支使用 `main`，提交 `Cargo.lock` 以固定应用依赖。构建产物、日志及本地环境配置由 `.gitignore` 排除；`.gitattributes` 统一文本换行。

macOS CI 对主分支推送和拉取请求执行格式、Clippy、测试及构建检查。
